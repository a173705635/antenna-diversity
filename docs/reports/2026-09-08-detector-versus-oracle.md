# 纯多径：数据驱动检测与理想 LCMV 的差距

条件：连续带限源和本地码、相位细化初始化、四天线、线性 DFE，无 RF 噪声/量化和外加干扰。
固定 EGC 捕获作为检测器入口，不使用理想分支选择捕获结果。

## 复现

```powershell
python python_sim_simplified/audit_multipath_oracle.py --refine --compare-detector
```

输出 `results/multipath_baseline_audit/detector_refined.json`。命令覆盖三个时延、两个相位，
并增加 113°/17° 非网格方向反例。最初六场景的 JSON 在新增反例前生成；独立反例另存 `offgrid.json`。
再次运行上述命令可得到包含七个场景的统一结果。

## 已验证的区别：抑制有效不等于时延检测正确

方向 110°/15° 恰在搜索网格上，功率 -6 dB。六个场景中，估计方向均正确，
检测驱动 LCMV 和理想 LCMV 都约 0.00386 m 全程 RMS。
但原检测器将相对捕获峰的偏移当作超额时延，出现以下错误：

| 真值 chip | 相位参数 | 原报告 chip | 双方向分离后连续估计 chip |
|---|---|---:|---:|
| 0.25 | 0 | 0.25 | 0.250000 |
| 0.25 | π | 0.25 | 0.250000 |
| 0.5 | 0 | 0.5 | 0.500000 |
| 0.5 | π | 0.25 | 0.500000 |
| 0.7 | 0 | 0.75 | 0.700033 |
| 0.7 | π | 0.5 | 0.700033 |

LCMV 只使用方向约束，时延报告错误不一定导致其失效。因此原有抑制通过测试不能证明时延估计正确。

## 本次修正范围

新增研究辅助 `refine_single_path_delays`：用假定 LOS 与检测器估计的反射方向组成矩阵，
检查条件后以伪逆分离两个分量；分别对连续本地码做归一化相关搜索，求两条延迟之差。
使用第 1～4 ms 数据，跳过初始有限记录/FIR 瞬态。计算包含捕获多普勒对应的码率。
不接收场景真值，不将已知反射方向送入此估计。

限定一个可分辨反射候选；同向/近退化矩阵、样本不足及搜索越界返回明确状态。
它不是多径数估计器，不处理任意多径；当前只由审查入口调用，尚未替换正常 pipeline 的时延字段。
源码对 `refined` 的定义是数值拟合位于搜索范围内，不代表统计置信度或正确性保证。

## 必须保留的反例：角度网格失配

真实方向 113°/17°，检测输出 115°/15°；真时延 0.5 chip、反射相位 π。

| 分支 | 全程码误差 RMS m | 实际反射方向幅度增益 |
|---|---:|---:|
| SINGLE | 31.3994 | 1 |
| EGC | 1.7170 | 0.05485 |
| 理想 LCMV | 0.00386 | 约数值零 |
| 检测驱动 LCMV | 4.0413 | 0.12903 |

连续时延估计约 0.499413 chip，虽然接近真值，但方向约束偏差使检测驱动 LCMV 比 EGC 更差。
这证明方案尚不能认定可靠；理想网格方向的成功存在条件依赖。

下一优先项是连续方向细化及方向不确定性/约束拒绝机制，随后再扩展噪声、多种方向和多径数。
不应仅调检测门限或只展示网格对齐的结果。
