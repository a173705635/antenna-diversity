# GF 商用运行状态管理原型

本轮新增 gf_runtime.py：逐星、逐历元维护当前四路连续弧和标定上下文，调用已有三态函数。新增 8 条测试实例，与 GF 判决及组合测试共 20 项通过。没有新增 RF 数据或定位性能结论。

## 运行规则

- 开机默认未确认，GF 输出不确定。
- 当前有效连续弧与当前标定收到外部确认后，才允许条件异常判决。
- 失锁/无效观测、未知误差界限、标定失效、连续弧或标定 ID 改变、数据间隔超限：撤销旧确认。
- 重捕获或温度回到标定范围，本身不恢复确认；必须收到新的外部事件。
- 数据中断所在历元不接受确认，避免同时携带的旧事件立即恢复降权。
- 时间倒退、非法门限撤销确认并报输入错误。

误差界限、门限及降权系数没有生产默认值。调用方明确提供参数。确认事件必须绑定四路弧与标定上下文，且由调用方保证是新事件，不能每历元重复提交缓存确认。该模块不负责证明外部确认正确。

## 与基础定位的关系

模块返回基础权重的乘数：疑似异常时使用配置的乘数，其余为 1。1 表示不增加 GF 降权，绝不表示观测有效或重启已失锁通道。基础定位仍应独立处理失锁、缺测、残差及自身质量控制。

当前只实现乘数接口，没有接入实际 PVT，因此尚不能声称“失效后定位无退化”。已确认降权退出时也可能重新暴露污染观测；端到端测试必须衡量误差尾部和恢复过程，不能只看系统仍输出位置。

## 事件回放

构造 12 个事件：开机、确认、失锁、重捕获、重新确认、超标定范围、恢复范围、重新确认、时间中断、重新确认、新弧、新弧确认。已观察到预期的撤销与恢复。

使用固定 20 mm 残差、10 mm 门限、1 mm 演示界限、25 ms 最大间隔、0.25 演示降权乘数；都不是独立标定参数。温度事件为布尔事件注入，未模拟真实温度或验证温度传感器。相同标定 ID 下的失锁与超温仍撤销确认，不能只比较 ID。

原始事件和代码哈希见 [结果](data/2026-09-12-gf-runtime/summary.json)。复现脚本 python_sim_simplified/audit_gf_runtime.py，拒绝覆盖旧结果。

## 接收机适配需求与剩余缺口

当前 tracking.py 输出 NCO、锁定指标、C/N0 等历史，但没有完整的商用四路弧 ID、可信半周标志、标定有效包络或分支确认接口。适配层必须聚合任一流的失锁/重启/周跳以更新弧 ID。不能把 phase_lock_metric 高等同于分支确认。

标定上下文应绑定设备、频率、天线/射频配置、温度与增益状态、版本和有效期；导线馈入标定不能独自覆盖天线相位中心及机壳效应。这些来源尚无实测证据。

下一步优先完成“外部输入能获得到什么程度”的适配验证与标定预算，随后在 PVT 回放中测试乘数启停。继续增加检测率样本前，需明确模拟的确认条件与实际设备缺口，不能通过人为置 True 获得商用结论。
