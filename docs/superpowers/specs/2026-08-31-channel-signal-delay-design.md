# 多通道信号序列延迟建模设计

日期：2026-08-31

## 1. 目标

为手机角点天线阵列加入每个接收通道独立的真实时间延迟，使不同通道不再只是同一序列乘以复数幅相系数，而是能够模拟馈线、射频前端、时钟/采样链路等引入的相对到达时间差。

实现顺序为：

1. 先修改完整工程 `python_sim/`，完成单元测试和全链路回归；
2. 再把相同物理模型同步到教学用精简工程 `python_sim_simplified/`；
3. 默认延迟全部为零，现有仿真结果保持不变。

本次不恢复已删除的 MATLAB 工程，也不在 DFE 中自动补偿通道延迟。

## 2. 当前模型与问题

当前场景生成方式可概括为：

```text
通道 m 的信号 = 天线/通道复响应 h_m × 公共信号序列 s[n]
```

`h_m` 已包含天线位置产生的空间相位、方向图、极化、遮挡、互耦和通道静态幅相误差。因此当前模型能够描述窄带阵列流形，但所有通道仍使用完全相同的时间采样序列；配置一个静态相位只能旋转整段序列，不能产生码边沿、包络或干扰门控边沿的样点错位。

新增模型需要同时保留：

- 天线位置导致的空间传播相位；
- 通道静态幅相误差；
- 通道真实时间延迟导致的序列移位和随频率变化的相位。

这三者物理含义不同，不能互相替代或重复计入。

## 3. 配置接口

### 3.1 完整工程

在 `PhoneArrayConfig` 中增加：

```python
channel_delay_ns: dict[str, float]
estimated_channel_delay_ns: dict[str, float]
```

默认配置为：

```python
channel_delay_ns = {"TL": 0.0, "TR": 0.0, "BL": 0.0, "BR": 0.0}
estimated_channel_delay_ns = {"TL": 0.0, "TR": 0.0, "BL": 0.0, "BR": 0.0}
```

含义如下：

- `channel_delay_ns`：仿真中的真实通道延迟，直接作用于每个通道的目标信号和干扰信号序列；
- `estimated_channel_delay_ns`：接收机认为的通道延迟，只作用于需要已知导向矢量的合并器；
- Blind Null 不读取估计延迟，只从实际延迟后的阵列数据估计协方差；
- 配置顺序不影响结果，运行时按 `active_antennas` 的顺序取值，支持手机四角中任意 2、3 或 4 根天线组合。

完整工程校验规则：

- 两个字典都必须完整包含 `TL`、`TR`、`BL`、`BR`；
- 数值必须有限且不小于零；
- 允许所有通道具有相同的公共延迟，不强制至少一个通道为零；
- 默认配置、参数化配置、研究快照、配置复制/规范化逻辑均需保留这两个字段。

### 3.2 精简工程

在 `python_sim_simplified/config.py` 的 `PhoneConfig` 中增加相同字段和相同默认值。精简工程保持教学定位，不复制完整工程的整套防御性校验。

## 4. 数学模型

设第 `m` 个通道的真实延迟为 `tau_m`，未加入通道延迟时的阵列复响应为 `h_m`，某一信号源的实际射频频率为 `f_src`。通道信号建模为：

```text
x_m(t) = h_m · s_IF(t - tau_m) · exp[-j 2π (f_c - f_IF) tau_m]
```

其中：

- `s_IF(t)` 是场景生成器中的复中频信号；
- `f_c` 是 GNSS 载频；
- `f_IF` 是复中频；
- 对目标信号，`f_src = f_c + f_doppler`；
- 对第 `k` 个 CW 干扰，`f_src,k = f_c + f_offset,k`。

序列延迟本身会产生 `f_IF + f_offset`（或 `f_IF + f_doppler`）对应的相位，额外乘积补足下变频本振移除的 `f_c - f_IF` 部分。因此对单频分量，合成后的总延迟相位等价于：

```text
exp[-j 2π f_src tau_m]
```

这样既能看到真实的样点/码边沿移位，也能保持正确的射频载波相位关系。

现有 `PhoneAntennaModel` 中的几何空间相位继续保留。通道延迟在场景生成阶段、每个信号源的阵列分量形成时单独施加，不能塞回天线阵列流形后再重复延迟序列。

## 5. 分数延迟实现

完整工程新增独立辅助模块，建议位置为：

```text
python_sim/antenna_diversity/gnss/channel_delay.py
```

公开的最小接口为：

```python
fractional_delay(signal, delay_samples, num_taps=33) -> ndarray
apply_channel_delays(component, delays_s, fs_hz, carrier_hz, if_hz) -> ndarray
delay_phase(delays_s, source_rf_frequency_hz) -> ndarray
```

实现规则：

- 使用 33 抽头（32 阶）的 Hamming 窗 sinc 分数延迟 FIR；
- 将延迟样点数拆成整数部分和 `[0, 1)` 内的分数部分；
- sinc 核按直流增益归一化；
- 离线卷积时补偿 FIR 的固定半长，只保留配置要求的延迟；
- 输入记录之外按零处理，输出长度与输入一致，前端无历史数据处补零，末尾超出记录的部分截断；
- `delay_samples == 0` 必须走精确直通分支，避免默认配置引入任何数值扰动；
- 只支持非负延迟，与配置校验一致。

精简工程同步同一算法，但可放在 `python_sim_simplified/gnss.py` 或一个简短辅助文件中，以可读性优先。

## 6. 场景生成接入

### 6.1 目标信号

完整工程当前先得到 `desired_true` 和公共 `desired_waveform`。修改后流程为：

1. 保留未含通道延迟的真实与估计阵列响应；
2. 形成未延迟的逐通道目标分量；
3. 按 `channel_delay_ns` 对每个通道的完整复中频序列做真实延迟，并补充本振残余相位；
4. `desired_steering_true` 在原真实响应上乘以 `f_c + f_doppler` 对应的真实延迟相位；
5. `desired_steering_assumed` 在原估计响应上乘以相同射频中心频率对应的估计延迟相位。

`desired_steering_true` 和 `desired_steering_assumed` 是中心频率处的窄带导向矢量；实际 `desired_component` 保留码序列带宽内的真实时间延迟效应。

### 6.2 干扰信号

每个干扰源分别处理：

1. 用该干扰源自己的 `f_c + f_offset` 计算延迟相位；
2. 对该干扰源的完整时间序列逐通道延迟；
3. 再与其他干扰源和目标信号相加。

因此不同频偏的干扰不会错误地共享同一个静态延迟相位。

### 6.3 真值与诊断量

场景 `truth` 至少补充：

- 按活动天线顺序排列的真实延迟 ns 和 samples；
- 按活动天线顺序排列的估计延迟 ns 和 samples；
- 目标信号真实/估计延迟相位；
- 各干扰源的真实延迟相位；
- 活动天线名称继续作为这些数组的顺序依据。

旧的 ULA 配置没有通道延迟字段，等价于全零延迟，行为保持不变。

## 7. 对合并算法的影响

- Single：选择到的单通道波形包含该通道真实延迟，但不存在跨通道相干叠加；
- EGC/MVDR 等已知导向矢量方法：使用 `estimated_channel_delay_ns` 构成的中心频率导向矢量；真实值与估计值不一致时会出现合并损失；
- Blind Null：只从真实延迟后的阵列采样估计干扰子空间，不直接使用估计延迟；
- 本阶段不在 DFE 前后做通道时间对齐，所以较大的相对延迟会真实表现为宽带/码域失配，而不只是一个可由静态相位完全抵消的误差。

这使模型能够用于研究“延迟估计误差对空域抗干扰和后续捕获跟踪的影响”，但暂不等同于完整的多通道硬件校准链路。

## 8. 测试与验收

先完成完整工程测试：

1. 零延迟时，延迟函数精确直通，默认全链路结果与修改前一致；
2. 复正弦输入经过分数延迟后，样点延迟和射频等效相位符合理论值；
3. 两通道设置非零相对延迟后，码边沿/门控边沿发生样点错位，两个通道不再只是常数复数倍关系；
4. 修改真实延迟会改变 `desired_component`、干扰分量和阵列协方差；只修改估计延迟不会改变实际采样，只改变假设导向矢量；
5. CW 干扰使用各自 `carrier_hz + offset_hz` 的正确延迟相位；
6. 手机四角任意 2、3、4 根天线组合均按 `active_antennas` 顺序工作；
7. 配置校验、复制和研究快照覆盖新增字段；
8. 完整工程现有测试全部通过（实现前基线为 680 项）。

随后同步精简工程：

1. 增加对应的零延迟、非零分数延迟、真实/估计延迟分离测试；
2. 保证完整工程与精简工程使用同一符号约定和公式；
3. 精简工程现有测试全部通过（实现前基线为 23 项）。

最后更新 README/配置示例，明确指出可在两个延迟字典中修改任意通道的 ns 值。

## 9. 本阶段不包含

- DFE 中的整数/分数延迟估计与自动校准；
- 随时间变化的时延、采样率偏差或各通道独立时钟漂移；
- 多径抽头、频率选择性射频通道或群时延曲线；
- 负延迟和循环移位；
- MATLAB 版本同步；
- 把通道延迟误认为天线几何位置误差并合并为同一个参数。

以上内容可在后续校准与硬件非理想阶段继续扩展。
