# 单欺骗源、正常初始化后：20轮连续接收机研究方法

本批按 [当前需求](RESEARCH_SCOPE.md) 研究，三天线为最低目标，四天线为主配置，二天线为性能对照。结果是软件仿真证据，不是商用验收或长期导航证明。详细数值由 `single_source_finalize.py` 从归档生成，见 [结果报告](SINGLE_SOURCE_TWENTY_REPORT.md) 和 [逐轮台账](SINGLE_SOURCE_TWENTY_LEDGER.md)。

## 1. 计数及版本

20轮均保存问题、待验证解释、源码改动、同录波前后结果、取舍及下一问题，沿同一条 RF→捕获→跟踪→观测→PVT 链串行发展。有失败并回退的轮次，不能写成20次成功改进。第7、16轮等被拒绝的机制也保留证据。第11轮重捕时标实现纠错不另计轮；原错误版本和中断缓存另存，未覆盖为成功结果。

基线是本批开始时的连续接收机 `results/single-source-twenty/baseline.py`：固定启动相位校准、短时解扩空间投影、单次捕获跟踪、逐历元码定位。冻结候选是第20轮完整源码 `selected.py`。最终审计发现状态交接缺陷后，该冻结版本撤销使用建议，修正版为 `single_source_receiver_fixed.py` / `audit_corrected.py`，结果严格分列，见第8节。这些名称不指代历史四条研究线中的同名备选，也不能把跨批统计直接相减。

RF前端未变的导航改动，复用由输入和前端AST哈希共同标识的实际RF跟踪缓存，重新解算前后PVT。前端有改动则重新运行RF链。复用不是新的RF运算，也不是额外迭代。20轮包含178组前后配对，356个模型侧结果，去重后196份导航结果；复演检查覆盖全部196份。

## 2. 输入、攻击和显式假设

阵列采用原手机75.9×160.9 mm的固定相位中心布局，输入始终先生成四路同步RF，二/三/四配置取 `[0,1]`、`[0,1,2]`、`[0,1,2,3]`。8颗卫星，2.046 MHz采样，GPS L1 C/A、0.9 MHz带限码及未知导航比特，接收机东向2 m/s运动，阵列姿态固定。

各星真实来向来自随机天空；单个欺骗源同时发射8个伪PRN，空间导向向量相同。默认源与第一颗卫星方向夹角60°，`near` 为重合，额外 `cluster` 将前三颗真实星设为源方向及其±0.5°，其余星保持原天空。几何变化不是多源攻击。

RF模型可写为

\[
\mathbf x(t)=\mathbf D(t)\left[\sum_i\mathbf a(\mathbf u_i)s_i(t)+\mathbf v(\mathbf u_s)\sum_i q_i(t)\right]+\mathbf n(t),
\quad a_m(\mathbf u)=e^{j(2\pi/\lambda)\mathbf b_m^T\mathbf u}.
\]

相位误差的标准差10°、幅度误差标准差1 dB，按种子抽取并在记录内固定。`drift` 另对四路整个录波乘 \(e^{j1.25mt}\)，m从0开始，因此包含明确的线性相对相位漂移。默认C/N₀为45 dB-Hz，`weak` 从启动起为35 dB-Hz。欺骗每PRN功率比真实信号高10 dB，0.3 s接入，默认假位置东偏100 m；`drag` 初始偏差0、以后以50 m/s增加假偏移。`absent` 在攻击期间移除全部真实信号；`return` 在0.8 s撤除攻击并恢复真实信号；`release` 在0.45 s撤除攻击，真实信号始终存在。

接收机输入仅有同步采样、码表、名义阵列导向、星历/时标及粗码周期辅助。模拟器真实位置、源方向、攻击开关和漂移率不传给算法。以下仍是强假设，不能隐藏：名义姿态/导向准确，星历可用，粗距离辅助可选对1 ms码周期（本批用10 km量化的生成距离构造），通道已同步且无采样时钟滑移。定位参考点仅用于坐标表示和名义几何。没有实测RF/IMU、手持旋转、车内多径、人体遮挡、温漂非线性、前端饱和或定点实现验证；本批没有引入IMU。

## 3. 实测启动标定、空间抑制及跟踪

初始100 ms进行阵列非相干捕获，以实际捕获/跟踪PRN建立1 ms本地相关模板。对去掉名义星间空间相位的通道交叉相关量做相位解缠，拟合

\[
\theta_{m,k}=\alpha_m+\omega_m t_k+\epsilon_{m,k},\qquad
\mathrm{SE}(\hat\omega_m)=\sqrt{\frac{\sum_k\hat\epsilon_{m,k}^2}{(K-2)\sum_k(t_k-\bar t)^2}}.
\]

仅当 \(|\hat\omega_m|>3\mathrm{SE}\) 时保留斜率，否则设为0并重新拟合截距。随后按样本时刻除去 \(e^{j(\hat\alpha_m+\hat\omega_m t)}\)。这是对线性偏差的估计补偿，并未证明可长期外推或消除幅度误差。弱信号下斜率估计偏差仍会积累。

每20 ms以1 ms解扩相关堆叠估计公共源子空间，沿用两步 `short_projector`。特征值比低于3时普通定向合成，否则对每星使用 \(\mathbf w_i=P\mathbf a_i/(\mathbf a_i^HP\mathbf a_i+0.01)\)。保留增益 \(g_i=\mathbf a_i^HP\mathbf a_i/M\)。真实星与源近方向会损失真实信号，天线数本身不能保证可用观测或良好几何。

每星有实际捕获、跟踪、失锁、重捕段；重捕产生新的弧ID。第12轮以实测C/N₀构造启发式期望锁定指标：\(S=10^{C/N_0/10}\cdot10^{-3},\ L_\mathrm{exp}=S/(1+S)\)。锁定指标小于 \(0.8L_\mathrm{exp}\)、C/N₀小于25或PLL误差不合格，连续5个1 ms历元后结束该弧。每次100 ms捕获之后才开始跟踪，头100个跟踪历元作为环路过渡段。这个门限不是经过台架标定的失锁概率模型。

伪距由实测码NCO和全局样本时刻形成，粗辅助仅选择1 ms周期；载波距离由同弧累计NCO相位形成。重捕后不能减掉段起点再套全局码时标，也不能跨弧直接作载波差。第11轮的非整数毫秒起点回归测试专门约束该问题。

## 4. 观测、星间约束与位置状态

观测准入要求范围有限、锁定指标≥0.5、C/N₀≥25、投影保留增益≥0.05。Hatch递推窗口20个10 ms观测历元，码-载波发散超过50 m或观测间断时重启：

\[
\bar\rho_{i,k}=\frac{\rho_{i,k}}{n_k}+\left(1-\frac1{n_k}\right)(\bar\rho_{i,k-1}+\phi_{i,k}-\phi_{i,k-1}),\quad n_k\le20.
\]

码定位同时解算XYZ和接收机钟差，以 \(\sigma_i\propto10^{(45-C/N_{0,i})/20}\) 加权。该值是相对权重，不是校准过的实际米级标准差。至少六颗有效星时逐一删除一星重解，最大水平解分离 \(S_k\le20\) m才允许码解作为一致校正；小残差/小解分离不等于信号认证，也不能排除一致性欺骗。

连续同弧公共卫星形成

\[
\Delta\phi_i-\Delta r_{\mathrm{sat},i}=-\mathbf u_i^T\Delta\mathbf p+\Delta b+\eta_i,
\quad H_i=[-\mathbf u_i^T,1].
\]

联合解算公共钟差等价于在保留正确噪声相关性的条件下消去公共项；星间再做差可显式写成 \(d_i-d_j=-(\mathbf u_i-\mathbf u_j)^T\Delta\mathbf p+(\eta_i-\eta_j)\)。这消除公共钟差，同弧时间差消除固定载波模糊度；不会自动消除通道×PRN差异偏差、周跳或错误锁定。

至少五星、H条件数≤1000、最大载波拟合残差≤0.1 m，再以 \(\hat\sigma_\phi^2=\max(0.02^2,\|r\|^2/(N-4))\) 和 \(Q=\hat\sigma_\phi^2(H^TH)^{-1}\) 检查水平最大主轴标准差≤0.5 m。通过后才允许载波增量参与状态更新。码一致时以0.1码解+0.9载波传播位置融合；码不一致时只传播合格载波。距离最近一致码解不超过0.2 s才允许以该传播结果临时发布。这个0.2 s时限和Q均为研究约束，不是20 m/50 m完整性保护界。

## 5. 初始化与中断后恢复

连续三个有限PVT的水平散布≤20 m才记录初始化完成时间。真实PVT解算中断后，来源隔离保持，不能凭之后偶发四星解就恢复发布。用原始校准RF及实际NCO相关，计算每星 \(s_i=\mathbf a_i^HR_i\mathbf a_i/(M\operatorname{tr}R_i)\)；至少六星 \(s_i\ge0.85\) 持续10个观测历元才恢复，并以当前新码解重建位置参考。这是原型恢复条件，仍有误接受/误拒绝风险。

这里的观测准入、弧管理和暂停发布属于用户要求的算法研究；没有新增文件/类型错误兜底、宽泛异常捕获或静默默认回退。

## 6. 时标、评分和独立验证

观测时刻为t，20 ms块缓冲后的理论最早可用时刻为t+0.02 s；计算运行耗时另记，未宣称可实时运行。攻击从0.3 s开始。主计数采用可用时刻≥0.3 s，所以包括少量攻击前/过渡观测延迟发布；报告另外统计观测时刻≥0.3 s的结果。`absent` 开头少量输出不能解释为真实信号完全消失后仍持续导航。

水平误差在可用时刻评分，分列全部机会数、实际发布数、≤20 m、≥30 m、≥50 m和最长无输出间隔；缺失不算合格导航。三个相关种子和重复时间历元不能当作几千个独立样本来给置信度。

开发种子113001。第20轮冻结后，留出种子114001/114013/114037、9类2 s场景，再加114037的漂移/弱信号/恢复4 s记录，共30份四通道录波、90个子集评估。初始基线只在预注册的114001正常/漂移/低信号3类做同录波比较，不能称为全部留出场景的基线对比。冻结后不按留出结果改模型。

启动起35 dB-Hz可能在攻击前未完成初始化。这类结果单列启动失败，不算用户明确排除的冷启动攻击验证，也不静默移除。最终条件统计还要求攻击前实际发布过位置，避免把仅有稳定候选PVT标记但未输出的位置当成操作就绪；不改写原始score，只在诊断汇总中明确区分。这个要求不使用位置真值筛选。

为直接覆盖“正常初始化后信号转弱”，补充协议另行预注册，保持模型不变，先45 dB-Hz，0.3 s后转35 dB-Hz；补充种子114101/114113/114137独立，统计单列。三天线114113虽初始化标记早于攻击，但此前未发布，单列为未操作就绪，不能称为一次正常运行后的抗欺骗验证。

常规持续单源攻击补充对照另用114201/114213/114237：45 dB-Hz、60°源夹角、100m假东偏、真实信号持续、2 s记录，无额外线性漂移；模型和协议在这些数据生成前冻结。它与主协议及转弱补充分列。两组补充共18次子集评估，不增加算法迭代轮数。

复验包括全部计数轮次的导航重演、源码AST变化、输入/源码哈希、原有1296个归档文件不变检查、原始RF完整重演及中断/重捕前缀因果检查。仿真只有2–4 s，不能外推成数分钟或无限时长保持精度。

## 7. 复现

在 `python_sim_simplified` 下使用 Python 3.11，设 `OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`。保留输入与缓存时，可运行：

```text
python single_source_audit.py
python single_source_rf_replay.py
python single_source_validation.py three
python single_source_validation.py four
python single_source_validation.py two
python single_source_finalize.py
python -m pytest tests -q
```

`freeze` 和 `inputs` 是建档步骤，已有冻结结果时不要重新覆盖；研究输入、源码和缓存应成套归档。重新执行完整前端验证可用独立输出目录，不应把命中缓存的调用写成RF重跑。

## 8. 冻结后状态交接审计与最小修复

冻结版第20轮将状态准入检查放在“公共星数≥4”的内部。当集合从6星变为另一组5星、共同星只有3颗时，未经解分离确认的码候选仍可能成为last；下一历元5颗星的载波增量通过检查后，会从错误的last传播并发布。

`state_handoff_probe.npz` 在实际无攻击跟踪观测上，仅于特定4个历元构造1000m东偏码观测并改变可用PRN集合，载波保留原实际跟踪值。冻结模型在0.53–0.55 s发布约1000m偏移。该反例验证的是接收机状态交接逻辑，未主张这些修改已由单源RF攻击完整生成，不计入RF检出/定位率，也不计作第21轮。

回归测试 `test_single_source_state_handoff.py` 先复现旧实现失败，再做两处修正：在所有状态更新之前统一要求“码解一致或载波传播一致”，并要求恢复重新锚定时码解一致。新增准入是观测状态模型的必要条件，不是异常兜底。冻结源码、原结果、反例全部保留，修正版另存，不追改20轮台账。

对全部36份记录、108个子集结果重跑修正版导航。RF前端AST和输入完全相同，复用原跟踪缓存；此为**冻结后纠错回放**，不是新留出验证。修正后重新运行全套测试，新增回归用例。后续应从修正版开展新的独立RF和台架验证，不能将这些回放直接当成商用证据。

```text
python -m pytest tests/test_single_source_state_handoff.py -q
python single_source_corrective_replay.py two
python single_source_corrective_replay.py three
python single_source_corrective_replay.py four
```
