# 连续误报与检测延迟：三窗确认留出实验

本轮实现了可选的连续窗口确认，使用独立连续正常数据标定门限，并完成 288 条留出轨迹、864 组策略结果及 96 次历史导航回归。**新策略没有通过导航要求，不替换默认单窗判据。** 正常误报降低，但部分接管确认变慢，错误 GNSS 更新在确认前污染了导航状态。

## 方法与冻结规则

复用 `carrier_stream` 与 `spatial_scores`，保持四角手机阵列、100 Hz 同步载波、8 PRN、固定导航系天空与单源方向、静止/转弯、80 s 时长。攻击从 20 s 开始，撤离组 30 s 撤离。沿用上一轮观测和 IMU 参数，详见 `NAVIGATION_FUSION.md`。仍为接管后载波模型与人为施加 PVT 拉偏，不是 RF 接管链路验证。

窗口分数为 $S_k$，低于阈值表示共同来源证据：

$$b_k=\mathbf1(S_k<\tau),\qquad
r_k=\begin{cases}r_{k-1}+1&b_k=1\text{ 且窗口相邻}\\b_k&\text{否则}\end{cases},\qquad
a_k=\mathbf1(r_k\ge m).$$

未知窗口输出未知并清零计数；时间断口也清零。第 $m$ 个窗口到达才确认，不追溯修改过去输出。确认前输出“尚无确认”，本实验继续允许 GNSS 更新；这项策略选择的污染代价计入导航结果。确认模块不锁存，导航消费者沿用告警后锁存隔离、无独立再准入则不恢复的规则。

每窗仍执行 cluster3 最小三星簇扫描，跨窗口的最小簇可以改变；本轮不是同一 PRN 簇的跨时跟踪，也未引入 IMU 姿态约束。3 窗数量预先确定，没有根据留出攻击调参。

| 策略 | 门限 | 确认窗数 |
|---|---:|---:|
| original | 0.01944701582434244 | 1 |
| three_only | 同 original | 3 |
| three_calibrated | 0.012710679080318886 | 3 |

原门限复用种子 710001 的 2000 条独立正常事件。新门限使用种子 730001–730024 × 静止/转弯，共 48 条连续正常轨迹：

$$\tau_{new}=\min\left(\tau_{old},\min_{j,k}\max(S_{j,k},S_{j,k+1},S_{j,k+2})\right).$$

严格小于比较保证这批标定轨迹没有三连窗确认。这只是“标定样本内零误报”的操作点，不是总体误报概率保证。程序先写 `frozen.json`，再生成留出种子 740001–740024 × 两种运动 × 六类场景，未用留出结果修改门限。

## 正常误报

| 策略 | 标定组误报轨迹/48 | 留出组误报轨迹/48 | 留出确认事件段数 | 留出隔离时间比例 |
|---|---:|---:|---:|---:|
| original | 17 | 14 | 93 | 22.326% |
| three_only | 5 | 5 | 15 | 7.277% |
| three_calibrated | 0 | 0 | 0 | 0% |

“事件段数”是确认状态从非告警进入告警的次数，包含第一次导航隔离后的检测事件；导航只在第一次确认时锁存。隔离比例按每条完整 80 s 为分母，第一次证据到达至轨迹结束为隔离时间，不把这段时间从分母剔除。

原门限在标定组最长出现 **11 个连续阳性窗口，即 1.1 s 的观测段**。三窗确认仍保留其中 5 条误报轨迹，说明独立噪声假设不成立；固定几何、转动和相关噪声均可能产生连续证据。本轮没有用无噪声对照分离三者贡献，不能据此断言全部由几何歧义造成。

正常留出总时长只有 48×80 s，即 1.067 h，且同一种子的两种运动共享天空，不是 48 份完全独立天空。**零误报不能证明每小时 ≤1 次、≤5 s 或 99% 导航可用率达标**，也没有覆盖温漂、手持遮挡、多径或长时间卫星运动。

## 攻击检测：必须排除提前误报

下表仅统计攻击开始前尚未告警的轨迹。各组分母变化是提前误报造成的，不删改总数据。时间为攻击起点至第一次攻击后确认，包含 1 ms 观测生产延迟。

| 策略 | 全部接管，检出/可评价 | 延迟范围，s | 3 PRN 接管，检出/可评价 | 延迟范围，s |
|---|---:|---:|---:|---:|
| original | 38/38 | 0.091 | 38/38 | 0.091–0.191 |
| three_only | 45/45 | 0.291 | 45/45 | 0.291–1.091 |
| three_calibrated | 48/48 | 0.291 | 48/48 | 0.291–5.291 |

慢拖、撤离两组的首次确认结果与全部接管相同，因为接管后的相位模型相同，PVT 拉偏斜率不会进入空间检测器。

20 mm 通道×PRN 固定偏差组：原策略有 11 条提前误报，其余 37 条仅 1 条在 34.991 s 后确认；三窗策略为 0/45，新门限为 **0/48**。确认并未消除这种差异偏差，且收紧门限进一步减少弱证据。该组与其他场景在偏差生成时消耗了不同的随机数，正常前段噪声并非逐样本相同；同场景的三种策略则严格共用分数流。

## 导航代价

独立留出中延迟最大的 3 PRN 轨迹为转弯、种子 740010。发现该反例后，用同一 IMU/PVT/初始误差进行三种策略配对复测；这是有意选取的失败诊断，不作为总体性能估计。

| 策略 | 确认延迟，s | 攻击后前 10 s 最大水平误差，m | 前 30 s 最大误差，m |
|---|---:|---:|---:|
| original | 0.091 | 5.586 | 24.531 |
| three_only | 0.591 | 13.908 | 46.179 |
| three_calibrated | 5.291 | 45.039 | 137.077 |

三种策略均没有提前误报。新门限下，确认前持续接受了 5 秒多的被污染 GNSS；隔离只阻止后续更新，不能消掉已经形成的位置、速度误差。**48/48 最终检出不能替代及时检出指标。**

同时对历史种子 720001–720004 × 两种运动 × 六类场景复跑 96 次配对导航。这组用于历史回归，不冒充新留出：

| 场景 | 原策略前 10 s 最坏误差，m | 新策略前 10 s 最坏误差，m |
|---|---:|---:|
| 正常，同样取 20–30 s | 9.852 | 0.761 |
| 全部接管 | 9.852 | 10.128 |
| 3 PRN 接管 | 9.852 | 46.806 |
| 慢拖 | 9.852 | 5.127 |
| 撤离 | 9.852 | 10.128 |
| PRN 差异偏差 | 49.079 | 49.079 |

历史正常组 GNSS 更新接受率由 73.30% 恢复到 100%，但这是更新率，不是经认证的导航可用率。历史 3 PRN 组最慢确认达到 **6.591 s**，有 **1/8** 在仍允许 GNSS 更新时误差已超过 30 m。偏差组新策略没有提前误隔离，8/8 都被持续拉偏；原策略部分轨迹因提前误报而未被拉偏的现象不能算正确识别。

## 复现与验证

在 `python_sim_simplified/` 中运行：

```powershell
python -m pytest tests/test_spatial_confirmation.py tests/test_navigation_fusion.py -q
python audit_spatial_confirmation.py --output results/spatial-confirmation --navigation
```

输出包含冻结规则和源码哈希、48 条标定分数、288 条留出分数、864 行检测结果、96 行导航结果。所有观测均为合成数据。失败轨迹可单独复现：

```python
import json
from pathlib import Path
from audit_navigation_fusion import experiment
p = Path('results/spatial-confirmation')
policies = json.loads((p/'frozen.json').read_text())['policies']
rows = []
for policy, (threshold, count) in policies.items():
    result, _ = experiment('turn', 'partial3', 740010, threshold,
                           confirmation_count=count)
    rows.extend(dict(policy=policy, **r) for r in result if r['spatial_gate'])
(p/'worst_delay_navigation.json').write_text(json.dumps(rows, indent=2), encoding='utf-8')
```

新增测试覆盖确认因果性、前缀一致性、时间断口/未知重置、单窗兼容及批量分数与逐窗消费者一致性；默认单窗的静止正常配对导航结果与上一轮已存结果逐字段相同。原默认行为保留。

本轮全量回归为 **231 passed，111.98 s**，保留已有零噪声 C/N0 除零警告 1 项。7 个源码哈希与输出记录一致，标定/留出分数尺寸及结果行数核对通过，新增入口通过编译检查。

## 判断与后续方向

本轮可确认三窗与门限收紧能降低当前样本的连续误报，**不能确认它能满足导航要求**。较保守的共同来源统计把部分接管证据也滤掉了；仅靠这个统计量调参数不是当前可接受的完整方案。

下一步应单独研究“候选证据出现后如何限制被污染更新”与“如何用额外观测排除正常几何”，并同时统计正常更新中断时长、攻击前污染和 10 s 导航误差。候选状态暂停 GNSS 可能减少污染，也可能恢复误报造成的可用性问题，不能未经实验直接启用。姿态/零偏估计、创新一致性、可信参考或 RF 观测闭环仍需各自验证；本轮没有将它们暗中加入以改善结果。
